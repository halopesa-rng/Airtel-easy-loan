O'LIVE TECH SCHOOL MANAGEMENT PLATFORM — MULTI-SCHOOL BUILD 2.0.0

WHAT THIS BUILD ADDS
- O'LIVE TECH platform brand; no fixed Green Star school is used as the active tenant identity.
- Public school registration at /register. Registrations remain pending until the Telegram Super Admin approves them.
- Each approved school receives a unique OLV-XXXXXXXX School ID and its own PostgreSQL database named olive_school_<schoolid>.
- Existing school-management modules continue to run against the selected school's database through a tenant-aware database router.
- School identity (name, address, contact, motto and logo URL) is loaded from the platform registry for login and generated school documents. Static pages apply the tenant brand at runtime.
- Telegram bot commands for school approval, activation/renewal, suspension, payment review, and administrator assignment.
- Manual M-Pesa receipt submission and explicit Super Admin confirmation before subscription activation.
- Server-side subscription checks block suspended and expired schools from using protected school APIs.
- O'LIVE TECH official contact details are deployment settings; no phone number or email is invented in this package.

IMPORTANT DATABASE DESIGN
CONTROL_DATABASE_URL stores platform registrations, tenant database names, subscription status, M-Pesa receipts, and Super Admin audit events.
TENANT_DATABASE_ADMIN_URL must point to the SAME PostgreSQL server as the platform database, using a PostgreSQL role allowed to CREATE DATABASE. The app provisions one database per approved school and applies the included school schema/migrations there.
DATABASE_URL is kept for compatibility bootstrap/migrations and can point to the same newly created platform database. Do not point it at the suspended/old database.

Render's standard managed Postgres setup may restrict CREATE DATABASE privileges depending on the credential/plan. Verify that the credential configured as TENANT_DATABASE_ADMIN_URL has CREATEDB permission before inviting schools. If it does not, provisioning will fail safely with an explicit error; do not enable public registrations until the database provisioning method is corrected.

NEW RENDER DEPLOYMENT
1. Create a NEW GitHub repository and upload the contents of this folder (not the parent folder).
2. In Render, create a new PostgreSQL database named olive-tech-platform-db. Do not connect the suspended old database.
3. Deploy from the included render.yaml Blueprint, or create a Node web service manually:
   Build: npm install
   Start: npm start
   Health check: /api/platform/health
4. Set DATABASE_URL, CONTROL_DATABASE_URL and TENANT_DATABASE_ADMIN_URL to the connection string for the NEW PostgreSQL server. CONTROL_DATABASE_URL may point to a database on that server dedicated to platform tables. TENANT_DATABASE_ADMIN_URL must have CREATEDB rights on the same server.
5. Set TELEGRAM_BOT_TOKEN from BotFather and SUPER_ADMIN_TELEGRAM_ID to your own numeric Telegram user ID. Only that ID can use bot commands. Never paste the bot token into chat or commit it to GitHub.
6. Set OLIVE_TECH_PHONE, OLIVE_TECH_EMAIL, OLIVE_TECH_WEBSITE and OLIVE_TECH_MPESA_PAYBILL to the actual official O'LIVE TECH contacts/payment details. These are intentionally blank until supplied by the owner.
7. Keep JWT_SECRET generated by Render (or set a random value of 32+ characters). Keep PLATFORM_ADMIN_KEY private.
8. Open /api/platform/health and then /register. Register a test school. The registration should remain pending.
9. In Telegram, run /schools and then /approve OLV-XXXXXXXX. Provisioning creates the school database and the first school administrator; school status becomes pending_payment.
10. The school submits its M-Pesa receipt on the registration result screen. Verify the receipt against actual M-Pesa records, then use /confirm OLV-XXXXXXXX RECEIPT 30. The final number is subscription days. Never activate based only on a screenshot or unverified claim.

TELEGRAM COMMANDS
/start or /help       Show help
/schools              List schools
/approve SCHOOLID     Approve registration and provision tenant database
/schoolinfo SCHOOLID Show school details
/payments             List pending M-Pesa receipts
/confirm SCHOOLID RECEIPT DAYS   Confirm receipt and activate/renew
/activate SCHOOLID DAYS          Activate/renew after you independently verify payment
/suspend SCHOOLID reason         Immediately suspend school access
/reject SCHOOLID reason          Reject pending registration
/assignadmin SCHOOLID username|Full Name|phone   Create an additional school admin

ADMINISTRATOR ASSIGNMENT
The first administrator account is created from registration details after approval. /assignadmin creates another school administrator and returns a randomly generated temporary password only to the authorized Super Admin Telegram chat. Share it with the intended person through a secure channel and instruct them to change it immediately; do not post it in a group.

LOGIN
Enter the School ID, choose your role, then sign in with your school account. School ID is included in the signed JWT so subsequent API requests are routed to the same tenant. The backend rejects missing/unknown school IDs and blocks suspended/expired tenants.

M-PESA
The app collects the payer phone, amount and receipt code; it does NOT automatically verify M-Pesa with Safaricom. Super Admin must independently verify the transaction before /confirm. Configure OLIVE_TECH_MPESA_PAYBILL with the correct official payment destination to display it on the registration screen.

OFFICIAL CONTACT
Service provider: O'LIVE TECH.
The official phone/email/website are shown from environment variables only. Set them to your real business contact before production. No third-party company contact is represented as O'LIVE TECH contact.

SECURITY / PRODUCTION NOTES
- Back up the new platform database and all tenant databases regularly.
- Restrict database network access and keep credentials in Render environment variables.
- Test database provisioning permissions before launch; if tenant CREATE DATABASE fails, do not allow production registration.
- A newly registered school is not accessible until Super Admin approval. Approved but unpaid schools can log in to submit payment, while other protected APIs remain blocked until activation.
- If subscription expiry passes, server-side checks suspend access. Super Admin can renew after payment verification.
- This package is syntax-checked but cannot be verified against your Render account, Telegram bot, or PostgreSQL permissions from this workspace. Complete the deployment acceptance tests before using real student data.
